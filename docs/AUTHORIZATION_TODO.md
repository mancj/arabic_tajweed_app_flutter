`10.0.2.2` для доступа к localhost хоста; физическое устройство — доступный IP Mac
или HTTPS API. Не считать изменяемый LAN IP постоянным адресом production.

## 3. Google: Firebase, OAuth-клиенты и SHA

### Android и Google Play

SHA-1/SHA-256 — публичные отпечатки сертификата, а не приватные ключи.
Они определяются **подписью установленного APK**, а не устройством или названием
режима. OAuth-клиент Android связывает package name и SHA-1 сертификата.

- [ ] Заменить `signingConfig signingConfigs.debug` в Android Release на
  настоящую release/upload-подпись. Настроить хранение keystore и паролей в CI.
- [ ] Получить SHA-1 и SHA-256 через Gradle `signingReport` для используемых
  debug и локальных release-подписей; проверить debug-подписи других Mac и CI.
- [ ] Настроить Play App Signing. В Play Console → App signing получить
  отпечатки **App signing key certificate** и добавить их в Firebase Android app.
- [ ] Различать upload key и app signing key: upload подписывает отправляемый AAB,
  а Play подписывает устанавливаемые APK своим app signing key.
  Добавить сертификат upload/local release в Firebase, если им подписан
  устанавливаемый напрямую APK. [Подпись Android](https://developer.android.com/studio/publish/app-signing).
- [ ] При обновлении app signing key зарегистрировать необходимые старые и новые
  сертификаты и проверить установки на поддерживаемых версиях Android.
- [ ] Если используем **Internal App Sharing**, добавить его отдельный тестовый
  сертификат: этот механизм переподписывает APK и отличается от internal testing.
  [Internal App Sharing](https://support.google.com/googleplay/android-developer/answer/9844679?hl=en).
- [ ] После SHA-настроек скачать актуальный `google-services.json`, убедиться,
  что он относится к нужному Firebase-проекту и package, пересобрать приложение.
- [ ] В Google Cloud Console того же проекта → Google Auth Platform → Clients
  проверить Android OAuth-клиенты для каждой реально используемой пары package/SHA-1.
  Если Firebase уже создал клиент, использовать его; недостающие пары создать,
  проверив отсутствие конфликта с клиентом другого проекта.

Google Play предоставляет сертификаты подписи; Firebase и Google Cloud
регистрируют их для авторизации. Само добавление SHA в Play не настраивает OAuth.

### iOS и общие настройки Google

## 7. Сценарии для каждой применимой ячейки матрицы

- [ ] Новый аккаунт: настоящий успешный вход, корректный профиль и UUID.
- [ ] Повторный вход и перезапуск: сессия сохранена, API принимает токен.
- [ ] Выход: сервер отзывает токен, устройство удаляет сессию; следующий вход
  позволяет выбрать другой аккаунт.
- [ ] Отмена выбора Google/Apple: остаёмся гостем без ложной ошибки.
- [ ] Нет сети, недоступный API и недоступный Firebase: понятное сообщение,
  повтор возможен, частичная авторизация не сохраняется.
- [ ] Повторное нажатие, уход с экрана, сворачивание и возврат из браузера:
  нет дублирующих запросов и применения запоздалого результата.
- [ ] Неверный, истёкший, отозванный или выданный другим проектом токен:
  backend отклоняет вход; заблокированный/удалённый аккаунт не восстанавливается случайно.
- [ ] Обновление приложения поверх старой версии сохраняет корректную сессию
  и прогресс; старые настройки окружения не ломают production.
- [ ] Первый вход на другом устройстве: отсутствие локального прогресса
  объясняется действующей локальной моделью; не обещаем ещё не реализованную синхронизацию.
