# ТЗ: приложение для обучения чтению на арабском

Статус: черновик по итогам обсуждения. Всё, что помечено `?`, ещё не решено.

---

## 1. Продукт

Приложение учит человека **читать по-арабски с нуля**: от узнавания отдельных букв до чтения слов.
Не разговорник, не словарь, не переводчик.

- Язык интерфейса: русский первым, английский вторым. Локализация закладывается в архитектуру сразу.
- Платформы: iOS, Android (Flutter).
- Целевая аудитория: русскоязычные новички, в том числе те, кто уже видел буквы, но не читает.
- Два трека: **«Чтение»** (от букв до слов) и **«Таджвид»** (правила чтения Корана). Второй доступен как продолжение первого либо сразу — по входному тесту, см. §8.

---

## 2. Ключевая идея: атом знания

Единица обучения — **не буква**, а **атом**.

```
Atom = (буква × форма) | огласовка | правило | слог
```

Всё — прогресс, очередь повторений, разблокировки — считается по атомам.
Буква считается освоенной, когда освоены все её атомы.

### Формы

Модель честная: у разных букв разное число форм.

| Тип буквы | Формы | Кол-во |
|---|---|---|
| Соединяющиеся с обеих сторон | изолированная, начальная, средняя, конечная | 22 буквы × 4 |
| Не соединяющиеся влево (`ا د ذ ر ز و`) | изолированная, конечная | 6 букв × 2 |

Итого ≈ **100 атомов-форм**.

Правило «не соединяется со следующей буквой» — не отдельный урок, а **факт, показываемый в момент знакомства с буквой**, с примером разрыва в слове. Это правило проверяемо: в упражнении на сборку слова неверное соединение засчитывается как ошибка.

### Формы вводятся по одной

Буква не вводится целиком. Формы открываются цепочкой, каждая — после освоения предыдущей:

```
ب-изолированная  requires: понятие «точки»
ب-конечная       requires: ب-изолированная в known
ب-начальная      requires: ب-конечная в known
ب-средняя        requires: ب-начальная в known
```

Порядок не случаен: конечная форма ближе всего к изолированной (та же буква плюс соединительная черта справа), поэтому идёт второй. Начальная и средняя отличаются сильнее.

**Буква в `known`** = все её формы в `known`. Именно это считают пороговые условия тем.

Следствие по длине: до порога «8 букв» нужно 32 атома в `known`. При вводе 1–2 атомов за урок это ~20–25 уроков до огласовок. `?` Порог подлежит калибровке — если окажется слишком долго, смягчается до «8 букв с известными изолированной и конечной».

### Формы показываются в слове

Соединённая форма — начальная, средняя, конечная — показывается не только глифом с татвилями (`ـبـ`), но и коротким **словом-примером с подсветкой этой буквы**. Глиф с хвостиками — абстракция; в слове видно, как буква на самом деле цепляется за соседей. Для несоединяющихся букв то же слово показывает разрыв. Слова задаются в контенте, по одному на форму, по возможности из уже введённых букв.

### Огласовки и слоги

Огласовка — **атом-знак**, а не свойство буквы. Их три:

```
фатха (َ ) → а
касра (ِ ) → и
дамма (ُ ) → у
```

Сочетание «буква + огласовка» — это атом типа **слог**, и такие атомы **не заводятся все 84 сразу**. Слог создаётся лениво, при первом появлении в задании, и дальше живёт как обычный атом. Так модель не раздувается, но проблемные сочетания всё равно всплывают: если человек путает `بِ`, этот конкретный слог попадёт в очередь повторений.

Аудио при этом нужно на все 84 сочетания — это требование к контенту, а не к модели прогресса.

### Модель буквы

```dart
Letter {
  id
  arabicName        // ألف
  ruName            // алиф
  sound             // фонетическое описание
  audioName         // аудио: имя буквы
  audioSound        // аудио: звук буквы
  connectsLeft      // bool — false для ا د ذ ر ز و
  forms             // [isolated, final] | [isolated, initial, medial, final]
  dots { count, position }   // 0..3, above | below
  strokePaths       // SVG-пути для обводки, по форме
}
```

## 3. Состояния атома

```
new → introduced → learning → known → mastered
```

| Состояние | Смысл | Переход дальше |
|---|---|---|
| `new` | ещё не встречался | урок вводит атом |
| `introduced` | показали, не спрашивали | первое задание |
| `learning` | в активной ротации | 3 верных подряд **с первой попытки** в ≥2 разных типах упражнений |
| `known` | распознаёт уверенно | подтверждение после интервала + ≥1 успех в «активной» механике |
| `mastered` | закреплено | — |

**Активная механика** = обводка или сборка слова. Одних тапов по вариантам недостаточно для `mastered`: узнавание ≠ воспроизведение.

Ошибка сбрасывает атом **на одно состояние назад**, не в ноль.

Дополнительно у атома есть два независимых флага, см. §6.4:

| Флаг | Смысл |
|---|---|
| `отложен` | временно выведен из ротации, не считается долгом |
| `weak` | засчитан по облегчённому критерию, требует добора в контексте |

Интервалы подтверждения: 1 день → 3 дня → 7 дней → 21 день. `?` — точные значения подлежат калибровке.

## 4. Типы упражнений

Одна переиспользуемая сцена с разными режимами. Каждое задание возвращает результат по **конкретному атому** — это единственный источник прогресса.

| # | Режим | Ввод | Проверяет |
|---|---|---|---|
| 1 | форма → имя буквы | выбор | узнавание |
| 2 | имя → выбрать форму | выбор | узнавание |
| 3 | найти букву в слове | выбор | позиционное распознавание |
| 4 | отличить похожие (`ب ت ث`) | выбор | точки |
| 5 | форма → её позиция | выбор | понимание форм |
| 6 | звук → выбрать букву | выбор + аудио | связь звук-графема |
| 7 | буква → выбрать звук | выбор + аудио | связь графема-звук |
| 8 | обвести букву по контуру | обводка | воспроизведение формы |
| 8а | написать букву по памяти | обводка без контура | воспроизведение без опоры |
| 9 | собрать слог/слово из форм | drag-and-drop | порядок RTL, соединение |

Плюс **карточка звучания** — не задание, а показ в блоке «новое»: звучит звук, одновременно показано написание. Связывает графему и звук до того, как начнутся проверки.

### Скорость как условие перехода

Узнавание становится чтением только когда оно автоматическое. Поэтому:

```
ответ верный и быстрее ~3 сек  → двигает атом вперёд
ответ верный, но медленный     → засчитывается, прогресса не даёт
```

`?` Порог в 3 секунды подлежит калибровке; для режимов с аудио и обводкой он другой.
Письмо занимает десятки секунд, и торопить в нём нечего: порог там 40 секунд
и по сути отсекает только брошенное задание.

### Порядок письма

Режимы 8 и 8а — один холст, разница только в том, виден ли контур. Порядок
всегда один: **сначала по контуру, потом по памяти**. Просить написать по
памяти букву, которую человек ни разу не вёл рукой, — это проверка до обучения.

За урок атом получает не больше одного задания на письмо: первый свой слот,
если букву ещё не вели рукой, и последний, если уже вели. Между ними остаётся
узнавание — иначе урок сводится к рисованию. Буква из повторения просится
по памяти, только когда она уже в `known`: на середине пути повторению
полезнее узнавание.

Ошибка в письме показывает контур — это и есть разбор верного ответа.
Атом без осевого SVG (все соединённые формы сейчас) обводкой не спрашивается.

### Чтение вслух — отдельная дорожка для добровольцев

**Произношение автоматически не проверяется.** Основной курс доводит до автоматизма узнавание форм и связь «графема ↔ звук»; правильность произношения остаётся на совести пользователя.

Параллельно идёт сбор записей для обучения будущей модели проверки. Это **отдельная дорожка, а не одиннадцатый режим упражнений**: раз записывают не все, чтение вслух **не влияет на состояние атомов** — иначе курс у добровольцев и у остальных расходился бы. У дорожки свой счётчик вклада.

#### Поток экрана

```
1.  Крупный слог:  بَ
    «Прочитай вслух» · кнопка записи
    Кнопки «послушать эталон» ещё НЕТ

2.  Запись 2–3 сек

3.  Проигрывается эталон, следом — своя запись

4.  «Ты сказал так же?»   [ Да ]  [ Нет ]
    обе кнопки нейтральные, одного веса, без зелёного и красного

5.  Событие уходит в лог, аудио — в очередь на выгрузку
```

Порядок необратим: кнопки «послушать» нет до записи. Дать её раньше — задание превращается в повторялку за диктором.

#### Вербовка добровольцев

Призыв показывается **не на старте**, а после того как человек уже занимается — ориентировочно после этапа 1 или пятой сессии, когда есть отдача и доверие. Отдельный экран объясняет, что записывается, зачем, где отключить и как удалить. Отказ — задание не появляется вообще; повторно спрашиваем не чаще раза в N сессий.

#### Что попадает в датасет

```
{ atomId, слог, эталонное_чтение, аудио,
  самооценка(да/нет), состояние_атома, попытка,
  устройство, версия_приложения }
```

Целевой текст известен заранее — это сильная метка, ради которой такие датасеты обычно и покупают. Самооценка — слабая метка, но полезная.

**Записи с «нет» ценнее правильных**: ошибки произношения это ровно то, чему модель должна учиться различать. Не фильтровать их.

#### Технические требования

- **16 kHz mono, Opus.** Для речи достаточно, размер вдесятеро меньше wav: запись 2–3 сек ≈ 10 КБ. Тысяча пользователей по 200 записей — около 2 ГБ вместо 20
- Сохранять **сырой кусок с полями тишины** по краям. Обрезка — при подготовке датасета, не на устройстве
- Писать версию приложения и модель устройства: микрофоны различаются сильно, это понадобится при обучении
- **Не собирать, пока нет места для выгрузки.** Записи на устройстве без отправки — просто занятая память

#### Юридические требования

Голос — персональные данные, в трактовке GDPR близко к биометрии. Это условие прохождения ревью в обоих сторах, а не формальность.

- **Явное согласие до первой записи**, отдельным экраном — не строчкой в общей политике
- **Отключение в любой момент** и удаление уже загруженного по запросу
- Честный `NSMicrophoneUsageDescription`. Формулировка «для распознавания речи» при отсутствующем распознавании — отклонение ревью
- Если в аудиторию попадают дети, требования жёстче (COPPA) и меняется возрастной рейтинг

### Дистракторы

Неверные варианты решают **две разные задачи** в зависимости от того, сколько атомов в задании.

#### Задания на один атом (режимы 1–8): дистрактор задаёт сложность

Диагностика тут не нужна — задание и так про один атом. Дистракторы определяют, что именно тренируется, и должны усложняться по мере освоения:

| Состояние атома | Дистракторы | Что тренируем |
|---|---|---|
| только введён | далёкие по форме (`ب` против `س`, `م`) | образ буквы целиком |
| `learning` | смешанные | узнавание среди похожего |
| последнее подтверждение перед `known` | минимальная пара (`ب ت ث`) | различение по точкам |

Минимальная пара — это **экзамен, а не стартовый режим**. Показывать её сразу на новой букве означало бы провалить человека за то, что он ещё не дошёл, и запустить откладывание (§6.4) там, где всё в порядке.

Побочный эффект градации полезен: `known` начинает означать «различает», а не «узнаёт при отсутствии конкурентов».

#### Составные задания (режим 9, слоги и слова): дистрактор даёт диагностику

Здесь атомов несколько, и при ошибке нужно понять, какой из них подвёл. Неверные варианты строятся так, чтобы отличаться от верного **ровно одной буквой**. Тогда выбор пользователя сам указывает на проблемный атом — отдельный микротест после провала не нужен.

#### Жёсткие ограничения на любой дистрактор

- **Только из введённых атомов.** `ث` не может быть вариантом ответа, пока `ث` не введена: иначе человек выбирает между знакомым и незнакомым, что не проверяет ничего, а просто отсеивает по узнаваемости.
- **Минимальная пара — только если обе буквы введены.** Частный случай предыдущего правила, но критичный: пара `ب`/`ث` бессмысленна, пока `ث` неизвестна.

#### Частный случай: урок про точки

На старте известны только `ا ب ت ث`, и пул дистракторов — это и есть минимальные пары. Это не конфликт с градацией, а свойство этапа: в уроке про точки минимальная пара **и есть предмет обучения**, а не подвох. Человек только что прочитал объяснение — логично сразу на нём и проверить. Градация начинает работать позже, когда пул введённых букв даёт из чего выбирать.

## 5. Сессия

- **12 заданий**, виден прогресс-бар.
- Ошибка → показать верный ответ + короткое объяснение → задание уходит **в конец очереди сессии**.
- Очередь может вырасти до **16 заданий максимум**. Дальше повторы не добавляются, иначе сессия становится бесконечной при плохом дне.
- Ответ со второй попытки не даёт продвижения по состоянию атома, но и не считается повторной ошибкой.

Жизней / сердечек нет.

## 6. Уроки: граф вместо расписания

Фиксированной программы «урок 7 вводит `ج` и `ح`» **нет**. Такое расписание убивает адаптивность: буква вводилась бы независимо от того, готов человек или нет.

Хранятся **ограничения и заготовки**, а не последовательность. Порядок уроков выводит алгоритм.

Учебный контент — граф знаний, темы, шаблоны уроков, тексты объяснений, данные по буквам — лежит **JSON-файлами в ассетах приложения**. Версионируется через git, работает офлайн, правка требует релиза. Формат сразу проектируется так, чтобы те же файлы можно было подтягивать с сервера, когда контент начнёт меняться чаще релизов.

### 6.1 Граф знаний

Узлы — атомы и понятия, рёбра — «что после чего *можно* вводить».

```
понятие «формы»    requires: —
понятие «точки»    requires: [ا, понятие «формы»]
ب                  requires: [понятие «точки»]
ث                  requires: [ب, ت]
понятие «соединение» requires: [≥2 буквы в known]
понятие «огласовки»  requires: [≥8 букв в known]
```

Это не порядок уроков, а рёбра. Условия бывают двух видов: конкретные зависимости (`ث` после `ب` и `ت`) и пороговые (`≥8 букв в known`).

Пороговые условия считаются по **`known`, а не `mastered`**. `mastered` требует подтверждения по календарю (1/3/7/21 день) — привязка тем к нему означала бы, что тема не откроется, пока не пройдут недели, даже если человек всё уже узнаёт. `known` — это «узнаёт уверенно», и этого для открытия следующего понятия достаточно.

### 6.2 Шаблоны уроков

Не «урок 7», а «урок такого типа». Шаблон задаёт структуру блоков и правила подбора, но **не конкретные буквы**.

| Шаблон | Когда применяется | Состав |
|---|---|---|
| `введение понятия` | открылось новое понятие | длинный intro + закрепление понятия + повтор |
| `введение буквы` | нагрузка в норме, в графе есть доступный атом | intro + 1–2 новых атома + закрепление + повтор |
| `повторение` | нагрузка выше порога | только повтор, новых атомов нет |
| `соединение` | понятие «соединение» открыто | слоги из освоенных букв |

Блок **повтора берётся из общей очереди**, а не из атомов самой темы: иначе буквы прошлых уроков не возвращались бы никогда, и интервальное повторение существовало бы только на бумаге. Из двенадцати заданий не меньше четырёх отдаются возврату, остальные — теме урока. Слоты под возврат резервируются первыми, иначе тема съедает весь урок. Если тема узкая и своими заданиями урок не заполняет, остаток тоже добирается из очереди: урок всегда двенадцать заданий, пока очереди хватает.

Очередь ранжируется по срочности: сначала атомы, не дошедшие до `known`, внутри группы — кого дольше всего не показывали. Интервалы из §3 работают на подтверждении `known → mastered`, а не на порядке очереди.

Общий скелет:
```
[intro]        объяснение — только если урок вводит новое понятие
[новое]        1–2 новых атома, показ без проверки
[закрепление]  до 8 заданий по атомам темы
[повтор]       4–8 заданий из очереди повторений
[итог]         что выучено, что открылось
```

Порядок блоков строгий: сначала материал урока и закрепление по нему, потом повтор старого отдельным блоком. Чередование атомов действует только внутри закрепления; повтор в него не подмешивается.

В `intro` для букв `ا د ذ ر ز و` обязательно показывается правило о несоединении влево.

### 6.3 Планировщик (на клиенте)

При каждом заходе проверяются четыре правила, **строго по приоритету** — срабатывает первое подходящее:

```
1. |отложенных| > 4        → шаблон «повторение»
                             + досрочно вернуть самый старый отложенный
                             гарантия темпа отключена

2. нагрузка > порога       → шаблон «повторение», новых атомов нет

3. 2 сессии подряд          → ввести один новый принудительно,
   без новых атомов          нагрузка игнорируется

4. иначе                    → взять из графа доступные атомы, ввести 1–2

затем: добрать блок повтора из очереди, выбрать шаблон по типу введённого узла
```

где `нагрузка = |атомы в learning| + размер долга по повторениям`, отложенные в неё не входят.

Порядок здесь и есть содержательное решение: гарантия темпа (3) сильнее нагрузки (2), но потолок отложенных (1) сильнее гарантии темпа.

Следствие: у кого `ب ت ث` не идут, тот **сам себе тормозит ввод новых букв** — получает уроки-повторения, пока долг не рассосётся. Кто идёт быстро — уходит вперёд. Расписание при этом ни у кого не «съезжает», потому что расписания нет.

### 6.4 Защита от застревания

Пункт 2 планировщика («нагрузка выше порога → новых атомов нет») сам по себе опасен: одна упрямая буква может заблокировать весь курс. Три предохранителя.

**Уровень 1. Атом откладывается**
```
отложен ← 5 ошибок суммарно ИЛИ 3 неудачные встречи в разных сессиях
```
Отложенный атом **исключается из расчёта нагрузки**: он не выучен, но перестаёт считаться долгом, и ввод новых букв разблокируется. Из ротации он уходит на 2–3 сессии.

**Уровень 2. Возврат другим способом**
Долбить одно и то же упражнение бессмысленно: если человек пять раз перепутал `ب` и `ت`, шестой показ тем же способом ничего не изменит. При возврате меняется подход, а не количество:
- самый лёгкий режим: далёкие по форме варианты
- подсказка про отличительный признак («у `ث` три точки — как три»)
- переход на обводку: моторика часто пробивает то, что не пробивает узнавание

**Уровень 3. Облегчённый зачёт**
После двух откладываний атом засчитывается по сниженным требованиям:
```
2 верных подряд в самом лёгком режиме   (вместо 3 подряд в ≥2 типах)
→ known, но с флагом weak
```
Флаг `weak` — это долг, а не амнистия:
- такие атомы **чаще обычного попадают в слоги и слова** на этапах 2 и 5
- флаг снимается при первом уверенном попадании там: буква доучивается в контексте, а не в лоб
- в справочнике «Алфавит» такая буква просто открыта, без отметки «освоено» — приложение не хвалит за то, чего не было

**Гарантия темпа**
```
если 2 сессии подряд не введено ни одного нового атома
    → ввести один новый принудительно, игнорируя нагрузку
```
Страховка на случай, когда долг по повторениям всё равно душит прогресс.

**Потолок отложенных: 4 одновременно**

Предохранители выше нужны, чтобы человек не застревал. Но если они срабатывают свободно, появляется противоположная беда: с плохим стартом можно набрать десяток отложенных букв и формально не застрять, фактически не выучив ничего.

```
если |отложенных| > 4
    → гарантия темпа отключается
    → досрочно вернуть самый старый отложенный, в облегчённом режиме
    → шаблон «повторение», пока счётчик не упадёт до ≤ 4
```

Это единственное правило, которое сильнее гарантии темпа: новые буквы не вводятся, пока не разобран накопленный хвост. Досрочный возврат нужен, чтобы хвост вообще мог разбираться — иначе отложенные просто ждут своей паузы, а урок-повторение работает вхолостую.

**Потолок долга**
Очередь повторений ограничена ~25 атомами. При переполнении самый застоявшийся откладывается — очередь физически не может расти бесконечно.

`?` Все числа (5 ошибок, 2–3 сессии паузы, 25 атомов в очереди, 2 сессии без новых, потолок 4 отложенных) подлежат калибровке на реальных данных.

### 6.5 Разделение ответственности

| Контент-менеджер решает | Алгоритм решает |
|---|---|
| какие понятия существуют и в каком порядке доступны | когда именно вводится следующая буква |
| условия разблокировки (рёбра графа) | сколько повторений в уроке и каких |
| тексты объяснений, аудио, примеры | какой шаблон применить сегодня |
| пороги нагрузки | нужен ли урок-повторение |

## 7. Этапы курса

Курс разделён на **два трека**.

### Трек «Чтение» — шесть этапов

```
1. Буквы: имена, формы, точки          ← визуальное распознавание
2. Соединение: короткие слоги          ← «как буквы слипаются», БЕЗ чтения вслух
3. Огласовки: фатха / касра / дамма    ← появляется звук слога
4. Мадд, затем сукун и шадда           ← долгота, потом отсутствие гласной
5. Чтение целых слов + танвин          ← появляется смысл
6. Доп. правила письма                 ← хамза, «Аль», та-марбута, лигатуры
```

### Трек «Таджвид» — отдельный курс

Правила произношения при чтении Корана: назализация, скрытие, слияние, знаки остановки.

Это **не седьмой этап, а второй трек**, и на то есть причины:
- правила применяются к сочетаниям слов, а не к буквам — другая механика
- без записи голоса их не проверить — другой способ проверки
- аудитория другая: сюда приходят люди, которые уже читают

`?` Содержание трека не проработано. Отдельный вопрос — входит ли он в этот продукт или становится следующим приложением.

Этапы 1–2 работают без огласовок, поэтому слоги там **немые**: показывают только форму и соединение. Задания вида «прочитай» появляются с этапа 3.

### Порядок букв

Алфавитный (алиф-ба-та) — задаётся рёбрами графа. Следствие: понятие **«точки»** обязано открыться вторым, сразу после алифа — иначе `ب ت ث` неразличимы. Побочный плюс: пользователь получает три буквы за один принцип.

Типичное начало (не расписание, а то, что выведет планировщик у среднего пользователя):
```
понятие «буква, имя, формы»   → ا
понятие «точки»               → ب ت ث
дальше — поток букв по алфавиту, темп задаёт нагрузка
понятие «соединение»          → при 2 буквах в known
понятие «огласовки»           → при 8 буквах в known
```

### Слоги

Синтетические комбинации из уже освоенных букв. Реальные слова появляются на этапе 5.

## 7а. Темы этапов 1–3

Полный список понятий, которые видит пользователь на главном экране. Этапы 4–6 пока не детализированы.

**Где лежит контент.** Граф и темы этапов 1–2 собраны целиком:
`assets/curriculum/stage1.json` (28 букв, 109 узлов, 23 темы) и
`stage2.json` (соединение, 12 узлов, 2 темы). Руками их не правят —
буквы описаны одной таблицей в `tool/build_curriculum.py`, он же
раскладывает их по узлам и темам.

Темы идут парами: «Буквы ج ح خ» вводит изолированные начертания, следующая
за ней «ج ح خ в слове» — остальные три формы тех же букв. Разделение нужно,
потому что урок вмещает 12 заданий: три буквы со всеми формами — это
двенадцать новых атомов, по одному заданию на каждый, и ни одного повтора.

Формы буквы зависят только от знакомства с её изолированным начертанием,
а не выстроены цепочкой конечная → начальная → средняя. Цепочка требовала
по уроку на звено: за один заход открывалось ровно одно новое ребро.

### Этап 1 · Буквы

| # | Тема | Открывается |
|---|---|---|
| 1 | Буква, её имя и вид | старт курса |
| 2 | Точки: чем различаются `ب ت ث` | `ا`-изолированная в `known` |
| 3 | Разные формы одной буквы | `ب`-изолированная в `known` |
| 4 | Буквы, которые не соединяются слева | введена `د` |
| 5 | Хамза — N из 5 | `ا` в `known` |
| 6 | Алфавит — N из 28 | счётчик, не разблокировка |

#### Хамза — часть алфавита, а не доп. правило

Для **чтения** достаточно узнавать пять начертаний как один звук:

```
ء   أ   إ   ؤ   ئ
```

Правила выбора носителя — на алифе, на вав, на йа или отдельно — нужны только чтобы **писать**. Приложение учит читать, поэтому эти правила в курс не входят вообще.

Все пять сразу после алифа дать нельзя: `ؤ` и `ئ` сидят на вав и йа, которых человек ещё не знает. Хамза раскрывается по мере появления носителей — граф это выражает напрямую:

```
أ, إ   requires: ا в known
ء      requires: أ в known
ؤ      requires: و в known
ئ      requires: ي в known
```

Тема открывается при вводе `أ`, дальше идёт счётчиком «2 из 5» и закрывается вместе с последним носителем.

| # | Тема | Открывается |
|---|---|---|
| 7 | Как буквы соединяются | ≥2 буквы в `known` |
| 8 | Разрыв в слове | тема 7 + ≥1 несоединяющаяся буква в `known` |

### Этап 3 · Огласовки

| # | Тема | Открывается |
|---|---|---|
| 9 | Что такое огласовка | ≥8 букв в `known` |
| 10 | Фатха, касра, дамма — 3 из 3 | тема 9 |

### Граф этапов 1–3

```

  ا-изолированная             requires: тема 1

тема 2 «Точки»                requires: ا-изолированная в known
  ب-изолированная             requires: тема 2
  ت-изолированная             requires: тема 2
  ث-изолированная             requires: ب-изол и ت-изол в known

тема 3 «Разные формы»         requires: ب-изолированная в known
  X-конечная                  requires: X-изолированная в known
  X-начальная                 requires: X-конечная в known
  X-средняя                   requires: X-начальная в known

тема 4 «Не соединяются слева» requires: введена د
  для ا د ذ ر ز و цепочка форм короче: изолированная → конечная

  أ, إ                        requires: ا в known
  ء                           requires: أ в known

  ئ                           requires: ي в known

тема 7 «Как соединяются»      requires: ≥2 буквы в known
  атомы-слоги, немые          requires: тема 7

тема 9 «Что такое огласовка»  requires: ≥8 букв в known
  фатха                       requires: тема 9
  касра                       requires: фатха в known

тема 11 «Чтение слогов»       requires: все три хараки в known
  атомы-слоги, озвученные     создаются лениво при первом показе

тема 12 «Долгие гласные»      requires: все три хараки в known
тема 13 «Буква без гласной»   requires: тема 12
```

Порядок букв внутри этапа 1 — алфавитный, задаётся рёбрами вида `ج-изолированная requires: ث-изолированная в known`.

### Этап 4 · Знаки, меняющие чтение

| # | Тема | Открывается |
|---|---|---|
| 12 | Долгие гласные (мадд) | все три хараки в `known` |
| 13 | Буква без гласной (сукун, шадда) | тема 12 |

Мадд идёт **первым**: это всё ещё «согласная + гласная», только долгая — прямое продолжение огласовок, и проверяется тем же способом. Сукун ломает саму схему слога (гласной нет вообще) и потому концептуально тяжелее.

Шадда объединена с сукуном в одну тему не случайно: шадда — это и есть буква без гласной плюс та же буква с гласной. Одно объясняет другое.

**Танвин на этап 4 не попадает.** Он не про долготу и не про отсутствие гласной, а про окончание «-ан / -ин / -ун», и встречается только в конце настоящих слов. Его место — этап 5, см. ниже.

#### Как проверяется мадд

Мадд — единственное место, где разница чисто на слух. Проверка идёт **от звука к написанию**:

```
звучит  «ба»  →  выбрать из [ بَ · بَا ]
звучит  «баа» →  выбрать из [ بَ · بَا ]
```

Микрофон не нужен, а тренируется ровно то, что надо — слышать долготу. Для сравнения, огласовки проверяются так же, но выбором из `بَ / بِ / بُ`.

#### Атомы этапа 4

Как и с огласовками: **знак — атом**, сочетания создаются лениво.

```
мадд-алиф (ـَا), мадд-вав (ـُو), мадд-йа (ـِي)   — 3 атома-знака
сукун                                            — 1 атом-знак
шадда                                            — 1 атом-знак
```

Конкретные сочетания «буква + знак» становятся атомами типа «слог» только когда реально встретились в задании. Иначе комбинаторика взрывается: 28 букв × 3 хараки × 5 знаков — это тысячи сущностей, и курс превратился бы в бесконечный.

### Этап 5 · Чтение слов

Первый этап, где появляется смысл: настоящие слова с переводом вместо синтетических слогов. Сюда же переезжает **танвин** — как тема «Окончания слов», потому что встретить его можно только в осмысленном тексте.

`?` Остальное по этапу 5 не проработано: откуда список слов, по какому принципу отбор, когда показывать перевод, собирается слово по слогам или узнаётся целиком.

### Этап 6 · Дополнительные правила письма

Правила **письма, а не произношения**. Без них настоящий текст не прочитать, поэтому они закрывают трек чтения.

| # | Тема | Что это |
|---|---|---|
| 15 | Артикль «Аль» (`الـ`) | солнечные и лунные буквы меняют чтение |
| 16 | Та-марбута (`ة`) | читается по-разному в паузе и в потоке |
| 17 | Лигатуры (`لا` и прочие) | сочетания, пишущиеся слитно |

**Хамза сюда не входит** — она часть алфавита и живёт на этапе 1, см. выше.

Та-марбута остаётся здесь осознанно: её чтение зависит от того, пауза после неё или поток, а это понятно только когда человек уже читает слова.

Знаки остановки из того же списка правил сюда **не входят** — они относятся к паузам при чтении, то есть к треку «Таджвид».

## 8. Экраны

### Главный

Списка уроков нет — уроки генерируются, впереди известен только следующий. Вместо него — **список понятий (вех)** с прогрессом разблокировки.

- Карточка «Продолжить»: следующий урок, стрик, текущая тема
- Ниже — темы, сгруппированные по этапам:

```
Этап 1 · Буквы
  ✓  Буква, её имя и формы
  ✓  Точки: чем различаются ب ت ث
  ▸  Алфавит  ▓▓▓▓▓░░░░░░░░  7 из 28
Этап 2 · Соединение
  🔒 Как буквы слипаются       нужно освоить 2 буквы
Этап 3 · Огласовки
  🔒 Фатха, касра, дамма       нужно 8 букв
```

Три свойства:

- **Список конечен и известен заранее.** Понятий ~12–15 на весь курс, они авторские и не зависят от темпа. Человек видит весь путь — чего генерируемая лента уроков не даёт.
- **Замок объясняет себя.** «Нужно 8 букв» — это ребро графа знаний, отрендеренное текстом. Настоящее условие, а не витрина.
- **Адаптивность спрятана внутри темы.** «Алфавит 7 из 28» — единственная строка, за которой стоит поток. Сколько уроков уйдёт на 28 букв, зависит от человека, и снаружи это не выглядит отставанием от графика.

Поимённый список будущих букв здесь **не показываем** — иначе это то же расписание, вид сбоку. Буквы живут в разделе «Алфавит».

### Урок
Одна сцена, переключающая режимы упражнений (см. §4).

### Алфавит (справочник)
Экран буквы открывается насовсем, когда все атомы буквы достигли `known`. Открытие показывается как награда в конце урока, но живёт постоянно в разделе «Алфавит».

Содержимое экрана буквы: все формы, точки, аудио имени и звука, правило соединения, примеры слов.

### Перескок через темы

Человек может считать, что часть курса ему уже знакома. Пускать по декларации нельзя: задания строятся выбором из **введённых** атомов, и в теме, до которой он «перепрыгнул», не окажется материала для вариантов ответа.

Поэтому перескок подтверждается делом.

```
На закрытой теме — кнопка «Уже знаю»
  → тест выборкой по всем темам до выбранной включительно
    (1–2 задания на букву, порог ~90%)
  ├─ сдал     → атомы этих тем получают known + флаг weak
  │             темы закрываются, выбранная открыта
  └─ не сдал  → показываем, где именно не дотянул,
                предлагаем начать оттуда
```

**Тест покрывает всё до выбранной темы, а не только её.** Иначе остаётся дыра: тема открыта, а предыдущие атомы не введены — и дистракторы брать неоткуда.

Флаг `weak` тут работает по прямому назначению: атом подтверждён одним ответом вместо трёх в разных режимах. Он остаётся в очереди повторений и добирается в контексте слогов и слов.

`?` Не проработано: размер выборки при большом числе тем, порог, что показывать при частичной сдаче.

### Состояния темы

| Состояние | Смысл | Вид |
|---|---|---|
| заблокирована | предыдущая тема не пройдена | серая, замок, «сначала пройдите …» |
| доступна | открыта, но не закончена | белая, контурная стрелка |
| брошена | заходили, но не дошли до конца | белая, счётчик освоенности |
| пройдена | дошли до конца урока | белая, галочка |

**Тему открывает прохождение предыдущей, а не освоенность её букв.** Граф
по-прежнему решает, что вводить внутри урока, но списком тем он не управляет:
иначе получается тупик «урок пройден, а следующий заперт» — например, когда
часть атомов не попала в урок из-за квоты заданий.

«Пройдена» — факт о занятии: человек дошёл до конца сессии. Ошибки не мешают,
провал возвращается в очередь внутри той же сессии.

Ближайшая доступная тема выделена цветом — к ней ведёт кнопка «Продолжить». Остальные доступные не подсвечиваются: иначе список выглядит разблокированным целиком, будто прогресс сломался.

Счётчик темы считает атомы в состоянии `known`, то есть **освоенность, а не факт прохождения урока**. Пройти урок и увидеть 3/5 — нормально: часть букв ещё не подтверждена скоростью и повторами. Поэтому счётчик показывается только у текущей и брошенной темы: у пройденной он читался бы как недоделка.

### Онбординг

Три ветки вместо двух — потому что треков теперь тоже два.

```
«Насколько вы знакомы с арабским письмом?»

  ├─ Совсем не знаком
  │    → трек «Чтение», урок 1
  │
  ├─ Знаю часть букв
  │    → диагностика по алфавиту (10–15 заданий)
  │    → проставляются статусы атомов
  │    → трек «Чтение» с нужного места
  │
  └─ Умею читать
       → входной тест: чтение слов с огласовками
       ├─ сдал      → трек «Таджвид»
       └─ не сдал   → трек «Чтение» с подходящего места
```

**Входной тест обязателен, декларации недостаточно.** «Умею читать» — ненадёжная самооценка: люди, читающие по слогам с ошибками, уверены, что читают. Пустить их в таджвид по заявлению означает отправить туда, где они не справятся, и потерять.

Формулировка результата при провале — не отказ, а маршрут: «начнём вот отсюда», с указанием, что именно уже засчитано. Человек не должен почувствовать, что его завернули.

## 9. Геймификация

Только **стрик** (дни подряд) + напоминания.

Сознательно не делаем: жизни/сердечки, XP и уровни, лиги, соревнование. Причина — религиозный контекст, где азартные и соревновательные механики неуместны.

## 10. Монетизация

Бесплатный старт → подписка. **Одна подписка на оба трека**, раздельных покупок нет: выбор при оплате снижает конверсию, а «всё включено» повышает воспринимаемую ценность.

- Первые **~5 уроков** бесплатно: человек успевает выучить несколько букв и почувствовать результат.
- Дальше paywall.
- `?` Раз уроки генерируются, «5 уроков» — это счётчик сессий, и у медленного пользователя он истечёт раньше, чем тот увидит результат. Альтернатива: привязать границу к **теме** («бесплатно до понятия „соединение“»), тогда все доходят до одинаковой точки ценности. Решить до релиза.
- Раздел «Алфавит» для уже открытых букв остаётся доступным всегда.

## 11. Хранение прогресса

Сейчас — **локально**, с прицелом на бэк.

- Интерфейс `ProgressRepository`, локальная реализация (Isar / Hive).
- Пишется **не снимок состояния, а лог событий**:
  ```
  { atomId, exerciseType, correct, attemptIndex, timestamp }
  ```
- Состояние атома = свёртка лога.

Тогда переезд на бэк — это загрузка накопленного лога, без переписывания логики. Если хранить только снимок, историю и возможность пересчитать модель мы потеряем.

## 12. Контент-задачи

### Аудио (~150–200 файлов)
- 28 имён букв, 28 звуков, 28 × 3 огласовки, набор слогов
- Готового лицензируемого пакета на рынке нет: ASR-датасеты записаны для распознавания и не годятся для проигрывания, коранические аудио — уровня аятов, не букв
- **Решение: генерируем через TTS.** Формат файлов фиксируем сразу, чтобы при необходимости заменить на живую запись без изменений в коде

### SVG-пути для обводки (~100 атомов)
- Источник: **Noto Sans Arabic**
- ⚠️ Глиф шрифта — это замкнутый контур (периметр буквы), а не траектория письма. Автоматическая выгрузка даёт «обведи букву по краю», а не «напиши букву»
- **Решение:** скелетизировать контуры скриптом → вручную поправить пути и проставить порядок штрихов. Часы работы, но не автомат
- Обводка не блокирует MVP: упражнения 1–7 и 9 работают без неё
- Сделано: `ا ب ت ث س ش ط ظ` в изолированной форме (`assets/svg/alphabet`).
  Атом ссылается на файл полем `tracing`; без него режимы 8 и 8а пропускаются

### Тексты
Все объяснения и правила — на русском, с заделом под английский.

### Бэкенд для записей произношения

Делается параллельно с клиентом. Минимальный контракт, чтобы две части не разъехались:

**Загрузка**
```
POST /recordings
  multipart: audio (opus) + meta (json)
  meta: { recordingId, anonUserId, atomId, слог, эталон,
          selfAssessment, atomState, attempt,
          device, appVersion, recordedAt }
```
- `recordingId` — **uuid, генерируется на клиенте**. Повторная отправка того же id идемпотентна: сеть ненадёжна, ретраи неизбежны
- `anonUserId` — стабильный анонимный идентификатор, **не связанный с email и аккаунтом**. Датасет не должен позволять опознать человека

**Очередь на устройстве**
- выгрузка батчами, **только по Wi-Fi**, с экспоненциальными ретраями
- локальный файл удаляется **только после ответа 200** — иначе записи теряются молча
- потолок локальной очереди: при переполнении дропаем самые старые и пишем это в аналитику, а не растём бесконечно

**Удаление**
```
DELETE /recordings?anonUserId=...
```
Право на забвение — обязательный пункт для ревью, не опциональный. Вызывается по кнопке в настройках.

`?` Сроки хранения сырых записей и политика их анонимизации — решить до первой выгрузки.
